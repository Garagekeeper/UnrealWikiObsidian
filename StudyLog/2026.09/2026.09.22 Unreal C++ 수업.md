# 2. GameplayCue
GameplayCue는 Gameplay Effect의 결과를 **사운드, 파티클, 카메라 셰이크 같은 시각·청각 연출**로 표현하는 기능이다.

![[2026.09.22 Unreal C++ 수업-1790049296833.webp]]

## GameplayCueNotify 종류
- `GameplayCueNotify_Actor`
	- 액터로 인스턴스화되므로 상태를 유지할 수 있음
	- 루핑, 지연 처리, 커스텀 로직 등에 사용
	- 버프·디버프처럼 일정 시간 유지되는 효과에 적합
- `GameplayCueNotify_Static`
	- 인스턴스화하지 않고 CDO를 재사용
	- 상태를 유지할 수 없음
	- 피격 이펙트, 총구 화염처럼 한 번 실행되는 효과에 적합

![[2026.09.22 Unreal C++ 수업-1790049425933.webp]]

## 주요 설정
- `Default Spawn Condition`
	- 확률이나 로컬 컨트롤 여부 등 Cue가 생성될 조건을 설정
- `Default Placement Info`
	- Cue의 위치와 회전, 대상 액터나 소켓에 붙일지를 설정
	- Hit Impact처럼 충돌 지점에 표시할 때는 보통 소켓에 부착하지 않음
- `GameplayCueTag`
	- Gameplay Effect의 Gameplay Cue 태그와 연결되는 값
	- `GameplayCue` 아래의 하위 태그만 지정 가능
- `Require Modifier Success to Trigger Cues`
	- Modifier가 실제 Attribute 값을 변경하는 데 성공했을 때만 Cue 실행

![[2026.09.22 Unreal C++ 수업-1790049604062.webp]]

## 이번 실습에서 만든 Cue
- `GameplayCue.Test.Hit`
	- `GE_Test04_Damage`에서 사용
	- `GCNS_Test04_Hit` 정적 Cue로 연결
	- Niagara Burst와 Camera Shake처럼 단발성 피격 연출 담당
- `GameplayCue.Test.Debuff`
	- `GE_Test04_Debuff`에서 사용
	- `GENA_Test04_Dot` 액터 Cue로 연결
	- Duration GE가 유지되는 동안 Looping Niagara 연출 담당

즉 Gameplay Effect는 게임플레이 결과를 처리하고, GameplayCue는 그 결과를 화면과 소리로 표현한다.

# 3. GameplayCue 적용 실습

## 3-1. 범위 안의 후보 탐색
`SphereOverlapActors()`로 반경 안에 있는 액터를 먼저 수집한다.

```cpp
TArray<TEnumAsByte<EObjectTypeQuery>> ObjectTypes;
ObjectTypes.Add(UEngineTypes::ConvertToObjectType(ECC_Pawn));
ObjectTypes.Add(UEngineTypes::ConvertToObjectType(ECC_WorldDynamic));

TArray<AActor*> IgnoreActors;
IgnoreActors.Add(this);
if (GetInstigator())
{
	IgnoreActors.Add(GetInstigator());
}

TArray<AActor*> OverlappingActors;
UKismetSystemLibrary::SphereOverlapActors(
	World,
	GetActorLocation(),
	Radius,
	ObjectTypes,
	AActor::StaticClass(),
	IgnoreActors,
	OverlappingActors
);
```

- Object Type으로 `Pawn`, `WorldDynamic`만 검색
- 자기 자신과 Instigator는 검색 대상에서 제외
- Overlap은 최종 피격 판정이 아니라 **검사할 후보를 좁히는 단계**

## 3-2. Line Trace로 시야 확인
Overlap된 후보까지 Line Trace를 발사하여 중간에 장애물이 있는지 확인한다.

```cpp
FHitResult HitResult;
const bool bHit = World->LineTraceSingleByChannel(
	HitResult,
	Origin,
	TargetLocation,
	ECC_Camera,
	TraceParams
);

const bool bConfirmed =
	bHit && HitResult.GetActor() == OverlappedActor;
```

- Trace에 맞은 액터가 처음 Overlap으로 찾은 액터와 같아야 최종 대상
- 장애물에 먼저 맞았다면 공격 대상에서 제외
- 성공한 선은 초록색, 실패한 선은 빨간색으로 그려 판정을 확인

## 3-3. 대상의 ASC 찾기
대상이 GAS를 사용하는 액터인지 `UAbilitySystemBlueprintLibrary`로 확인한다.

```cpp
UAbilitySystemComponent* TargetASC =
	UAbilitySystemBlueprintLibrary::GetAbilitySystemComponent(OverlappedActor);

if (!TargetASC)
{
	continue;
}
```

- ASC가 없는 액터에는 Gameplay Effect를 적용하지 않음
- 대상 클래스에 직접 강하게 의존하지 않고 ASC 보유 여부로 처리 가능

## 3-4. EffectContext에 충돌 정보 전달
GameplayCue가 실제 충돌 위치와 방향을 사용하려면 `FHitResult`를 EffectContext에 넣어야 한다.

```cpp
FGameplayEffectContextHandle EffectContextHandle =
	TargetASC->MakeEffectContext();

EffectContextHandle.AddSourceObject(this);
EffectContextHandle.AddInstigator(this, this);
EffectContextHandle.AddHitResult(HitResult, true);
```

- `AddSourceObject()` : 효과를 발생시킨 오브젝트 기록
- `AddInstigator()` : 효과의 가해자 기록
- `AddHitResult()` : Impact Point, Impact Normal 등 충돌 정보 전달
- 두 번째 인자 `true`는 HitResult를 새 값으로 교체하면서 복사

> Hit Cue를 정확한 충돌 지점에 생성하려면 `AddHitResult()`가 핵심이다. 이 정보가 없으면 Cue가 대상 액터의 피벗 위치 등을 기준으로 실행될 수 있다.

## 3-5. Gameplay Effect Spec 생성 및 적용

```cpp
FGameplayEffectSpecHandle SpecHandle = TargetASC->MakeOutgoingSpec(
	HitEffectClass,
	EffectLevel,
	EffectContextHandle
);

if (SpecHandle.IsValid())
{
	TargetASC->ApplyGameplayEffectSpecToSelf(*SpecHandle.Data.Get());
}
```

처리 순서는 다음과 같다.

1. EffectContext 생성
2. Context에 Source, Instigator, HitResult 기록
3. Effect Class와 Level로 Spec 생성
4. Spec 유효성 확인
5. 대상 ASC에 Gameplay Effect 적용
6. GE에 등록된 GameplayCue 태그에 대응하는 Cue 실행

## 3-6. Debuff 적용
`TestDebuff()`는 지정한 `Target`에 Duration Gameplay Effect를 적용한다.

- 단순 대상 지정이므로 Line Trace의 HitResult는 사용하지 않음
- `GE_Test04_Debuff`가 유지되는 동안 `GameplayCue.Test.Debuff` 실행
- Actor형 Cue인 `GENA_Test04_Dot`가 루핑 이펙트의 생성과 제거를 담당
