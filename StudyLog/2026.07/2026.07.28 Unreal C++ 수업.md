## 1.  WeaponActor 추가하기
무기가 채찍처럼 자유자재로 움직일 수 있어야하면 스켈레탈 메시를 사용하지만 그렇지 않은 경우는 스태틱 메시로 사용하는 것이 성능적인 면에서 이점이 있다.

### 메시 및 콜리전 추가하기
[콜리전 레퍼런스](https://dev.epicgames.com/documentation/unreal-engine/collision-response-reference-in-unreal-engine?application_version=5.7)
Mesh를 루트로 설정하는 이유
- 추후에 무기를 줍고 버리는 기능을 추가할 예정인데, 무기를 버릴 때 물리 시뮬레이션이 들어갈 예정
- 물리 시뮬레이션을 할때는 루트에 물리를 가진 컴포넌트가 있는게 좋다.

메시에 콜리전 달고, 메시 자체는 No collision으로 해준다. 이 때 콜리전 사이즈를 넉넉하게 잡고 오버랩(일단은 폰만)
Mesh에 Collsion을 추가하고 Mesh 자체는 No collision으로 설정한다. 스태틱 메시도 콜리전을 제공하긴 하지만, 우리가 원하는 형태로 조절하기 힘들기 때문에 별도의 Collision을 추가해서 활용하도록 하자.

CollisionEnabled의 속성
- NoCollision : 말 그대로 어떠한 충돌감지도 하지 않는 경우
- Probe Only : 충돌 정보는 알고 싶은에 물리는 안하고 싶을때
- Query Only : 공간 쿼리(raycast, [[Sweep]], overlap)만 사용하고 싶을 때
- Physics Only : 물리 시뮬레이션에 의한 충돌만 사용하고 싶을 떄떄
- Collision Enabled : 쿼리, 물리 시뮬레이션 둘 다 사용하고 싶을때

{

### 원할때만 오버랩 켜주기

항상 콜리전을 켜놓으면 같은 대상에게 중복된 데미지를 입히는 등의 의도하지 않은 동작이 발생할 수 있다. 이걸 방지하기 위해서 진짜 필요할때만 콜리젼을 켜서 관리하도록 하자.

제일 먼저 무기를 들고 있는 소유자는 자신의 무기에의해서 피해를 입지 않아야한다. 
```cpp title:자신의\_충돌을 무시
HitArea->IgnoreActorWhenMoving(OwnerCharacter.Get(), true);// 자기 자신이랑은 충돌 안하게 (만약을 대비)
```


그 다음으로는 무기를 휘두르지 않았을 때 오버랩이 발생하는 경우도 막아줘야한다. 이 경우 **평소에는 콜리젼을 끄고** 다니다가 무기를 공격을 하면 **원하는 타이밍에 콜리젼을 활성화**에 처리를 한다. 여러 방법이 있을 수 있지만, Anim Notify State를 통해서 실습을 진행했다. (대상이 격하게 움직이면 이래도 중복 들어감) Notify Begin, End를 통해서 데미지를 입힐 수 있는 구간을 정하고 그 구간에만 콜리젼을 활성화 시킨다.

// 구간이 시작되면 호출되는 함수
void UAnimNotifyState_AttackEnable::NotifyBegin(USkeletalMeshComponent* MeshComp, UAnimSequenceBase* Animation, float TotalDuration, const FAnimNotifyEventReference& EventReference)
{
	Super::NotifyBegin(MeshComp, Animation, TotalDuration, EventReference);

	//인터페이스가 있는지 확인하고 인터페이스의 함수 호출
	WeaponOwner = Cast<IWeaponUserInterface>(MeshComp->GetOwner());
	if (WeaponOwner)
	{
		// 순수 가상함수로 구현하였기 때문에 이름으로 바로 호출
		WeaponOwner->OnWeaponAttackState(true);
	}
}

// 구간이 종료되면 호출되는 함수
void UAnimNotifyState_AttackEnable::NotifyEnd(USkeletalMeshComponent * MeshComp, UAnimSequenceBase * Animation, const FAnimNotifyEventReference & EventReference)
{
	Super::NotifyEnd(MeshComp, Animation, EventReference);
	if (WeaponOwner)
	{
		WeaponOwner->OnWeaponAttackState(false);
		WeaponOwner = nullptr;
	}
}

// 무기를 장비할 때 생성되는 함수
void AWeaponActor::OnEquipped(AActor* InOwner, ECollisionChannel TargetChanel)
{
	SetOwner(InOwner);
	OwnerCharacter = Cast<ACharacter>(InOwner);
	FAttachmentTransformRules AttachRules(
		EAttachmentRule::SnapToTarget,
		EAttachmentRule::SnapToTarget,
		EAttachmentRule::SnapToTarget,
		true
	);

	// 소유자가 유효하면
	if (OwnerCharacter.IsValid())
	{
		// 무기를 원하는 소켓에 붙인다.
		AttachToComponent(OwnerCharacter->GetMesh(), AttachRules, AttachSocketName);
		HitArea->IgnoreActorWhenMoving(OwnerCharacter.Get(), true);// 자기 자신이랑은 충돌 안하게 (만약을 대비)

		// 인터페이스 상속 받는지 확인
		IWeaponUserInterface* WeaponUser = Cast<IWeaponUserInterface>(OwnerCharacter);
		if (WeaponUser)
		{
			// 여기서 델리게이드에 함수를 바인딩 시킨다.
			// 해당 델리게이트가 발동되면? 실행할 함수를 넣어준다.
			WeaponUser->GetWeaponAttackStateChangedDelegate().BindUFunction(this, FName("AttackEnable"));
			WeaponUser->SetWeapon(this);
		}
	}
}

// 최종적으로 Notify에 의해 실핼될 함수
void AWeaponActor::AttackEnable(bool bEnable)
{
	if (bEnable)
	{
		HitArea->SetCollisionEnabled(ECollisionEnabled::QueryOnly);
	}
	else
	{
		HitArea->SetCollisionEnabled(ECollisionEnabled::NoCollision);
	}
}

## 2 기타 팁
- 테스트용 맵을 많이 만들자
	- 플레이 버튼을 눌렀을 때 원하는 기능을 바로 테스트 하는 환경이 제일 좋은 환경
	- 테스트 맵이 많으면 디버깅이 쉽다
- FSting을 %s로 찍으려면 \*를 앞에다 붙여서 사용해야한다.
- 무기는 상속을 좀 피하자 (Data Driven을 위해서)
	- Data Driven 기반의 무기를 만드려면 상속은 최대한 피하는것이 좋다. 무기마다 상속을 챙기면 각 무기의 속성을 데이터로 관리하기 어려워진다. 되도록이면 하나의 공통 클래스를 두고 에셋이나 속성을 데이터를 기반으로 변경시키는게 좋다.
