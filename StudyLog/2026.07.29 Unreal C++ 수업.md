### 데이터 에셋 만들기


게임에 사용할 데이터 에셋 또한 cpp 상에서 구현이 가능하다. UPrimaryDataAsset을 상속받아서 원하는 속성을 넣고 데이터 에셋을 구성할 수 있다. 에셋을 로딩할 때 동기/비동기 두 가지 방식으로 나뉜다. 동기 방식은 block방식 즉 로딩이 끝날때까지 기다리기 떄문에 끊김 현상이 발생할 수 있다. 비동기 방식은 non blocking이라 로딩이 끝나기를 기다리지 않고 다른 작업을 이어하기 때문에 끊김이 없다.

TSotObjectPtr과 FSoftObjectPath
FSotObjectPtr은 하드 레퍼런싱 예방과 Lazy Loading을 위해서 사용된다.
공식문서의 설명에 따르면 TSotObjectPtr은 기본적으로 FSoftObjectPath를 감싸는 TWeakObjectPtr이다. 약한 참조를 통해서 에셋을 유지하기 바로 사용하는 것이 아니라 `.Get()`함수를 통해서 실제 에셋의 포인터를 가져와야 한다. 이 때 TSoftObjectPtr이 참조하는 에셋이 메모리에 로드되지 않았으면 nullptr을 반환한다.

모든 에셋이 로드되는 상황을 막기위해 TSotObjectPtr를 사용하는데 메모리에 없다는 정보로는 부족하다. 그래서 TSoftObjectPtr은 내부에 FSoftObjectPath라는 구조체를 감싸고 있다. FSoftObjectPath는 해당 에셋의 주소(디스크 상의 주소)를 가지고 있어서 다른 로드 함수들에게 이 경로를 전달해주면 에셋이 로딩되고 TSoftObjectPtr이 가리키는 포인터 또한 실제 로딩된 에셋의 주소를 가리킨다.

### 데이터 에셋 로딩하기

 `StreamableManager`를통해 TSoftObjectPtr이 참조하는 에셋을 로딩할 수 있다. 앞서 말했는 로딩 방식이 2가지가 존재하는데, `SynchronousLoad` 와 `RequestAsyncLoad`가 이에 해당한다. `SynchronousLoad`은 단순한 블로킹 로딩이라 에셋의 크기가 커지면 메인 스레드를 오래 붙잡을 확률이 있다. 이런 경우에는 `RequestAsyncLoad`를 사용해 비동기 로딩을 진행하고 완료되면 델리게이트를 호출한다. `RequestAsyncLoad`에는 에셋들의 SoftObjectPath가 담긴 컨테이너와 델리게이트를 넘겨준다. 반환 값으로 `TSharedPtr<FStreamableHandle>`타입의 핸들을 반환 하는데 이 핸들을 통해서 에셋의 로딩 여부등을 알 수 있다. Unity의 Addressible과도 비슷한 느낌인 것 같다.
 예제에서 MoveTemp를 통해 lvalue를 rvalue로 전환해 넘겨 줬는데 이건 [[rvalue, lvalue]]를 확인해보자. 람다 전체를 복사하는게 아니라 이동을 해서 리소스 사용을 줄이는 방식인 것 같다.
 

```cpp file:WeaponDataAsset.cpp
#include "Data/WeaponDataAsset.h"
#include "Engine/AssetManager.h"
#include "Engine/StaticMesh.h"

TSharedPtr<FStreamableHandle> UWeaponDataAsset::RequestDataLoad(FStreamableDelegate InDelegate)
{
	// 로드할 에셋들의 경로를 TArray에 담기
	// SoftObjectPtr은 내부에 경로를 가지고 있음
	TArray<FSoftObjectPath> TargetsToLoad;
	TargetsToLoad.Add(Mesh.ToSoftObjectPath());

	// 에셋 로드에 사용되는 클래스
	// 보통은 싱글톤 같이 사용되는 곳에 넣는게 좋다고 한다.
	FStreamableManager& Streamable = UAssetManager::GetStreamableManager();
	
	// 비동기 로딩을 요청하고 핸들을 반환한다.
	return Streamable.RequestAsyncLoad(TargetsToLoad, MoveTemp(InDelegate));
}

// 현재는 lazy loading asset이 하나밖에 없어서 이런식으로 핸들 없이 로딩 여부를 확인할 수 있다.
bool UWeaponDataAsset::IsLoaded() const
{
	return Mesh.IsValid();
}
```

```cpp file:ActoinCharacter.cpp
void AActionCharacter::EquipWeapon_Implementation(UWeaponDataAsset* InWeaponData)
{
	// 이전 무기 해제
	if (CurrentWeapon.IsValid())
	{
		CurrentWeapon.Get()->DropWeapon();
		CurrentWeapon = nullptr;
	}

	// 현재 무기 데이터 갱신
	currentWeaponData = InWeaponData;
	
	//현재 무기가 로드된 적 없는 경우 
	if (!InWeaponData->IsLoaded())
	{
		
		// 로딩이 종료 되었을 때 실제 요청한 무기가 맞는지 확인용
		// 로딩중에 무기를 바꿀 수 있으니까는
		UWeaponDataAsset* Requested = InWeaponData;
		// 데이터 에셋 로딩 요청
		InWeaponData->RequestDataLoad(
			//로딩이 완료 되었을 때 실행되는 람다
			//FStreamableDelegate::CreateWeakLambda() 대상 객제차 죽으면 로딩 중단
			FStreamableDelegate::CreateWeakLambda(this, [this, Requested]() {

				// 무기를 바꾸지 않은 경우만 소환
				if (currentWeaponData == Requested)
						SpawnWeaponActor();
			})
		);
	}
	else
	{
		SpawnWeaponActor();
	}

}

void AActionCharacter::SpawnWeaponActor()
{
	if (!currentWeaponData)
	{
		return;
	}
	
	// SpawnActorDeferred를 통해서 생성을 지연시킬 수 있음
	// 정확히 말하면 다음 단계로 진행하려면 끝났다고 표시 해야함
	CurrentWeapon = GetWorld()->SpawnActorDeferred<AWeaponActor>( // 생성 시작
		AWeaponActor::StaticClass(),
		FTransform::Identity,
		this,
		this);

	// 무기가 정상적으로 소환이 되었다면
	if (CurrentWeapon.IsValid())
	{
		// 무기에 데이터 에셋을 넘겨서 초기화
		CurrentWeapon->InitalizeWeapon(currentWeaponData);
		// 생성이 끝남 (스폰 완료, BeginPlay까지 진행)
		UGameplayStatics::FinishSpawningActor(CurrentWeapon.Get(), FTransform::Identity);
	}
	
	// 무기를 플레이어의 소켓에 붙이는 함수
	CurrentWeapon->OnEquippedToTarget(this, ECC_Enemy);
}
```

```cpp file:WeaponActor
void AWeaponActor::InitalizeWeapon(UWeaponDataAsset* InData)
{
	// 에셋을 통한 초기화
	WeaponData = InData;
	Mesh->SetStaticMesh(WeaponData->Mesh.Get());

	HitArea->SetCapsuleHalfHeight(WeaponData->hitAreaHalfheight, false);		// 뒤의 bool은 크기 변경시 오버렙 바로 갱신할거냐
	HitArea->SetCapsuleRadius(WeaponData->hitAreaRad, false);

	HitArea->SetRelativeLocation(WeaponData->LocationOffset);

	AttachSocketName = WeaponData->AttachSocketName;
	AttackDamage = WeaponData->AttackDamage;

}

// 장착을 위해 공개된 함수
void AWeaponActor::OnEquippedToTarget(AActor* InOwner, ECollisionChannel TargetChanel)
{
	OnEquipped(InOwner, TargetChanel);
}

// 실제 장착을 위해 시용하는 내부 함수
void AWeaponActor::OnEquipped(AActor* InOwner, ECollisionChannel TargetChanel)
{
	SetOwner(InOwner);
	OwnerCharacter = Cast<ACharacter>(InOwner);
	
	FAttachmentTransformRules AttachRules(
		EAttachmentRule::SnapToTarget,
		EAttachmentRule::SnapToTarget,
		EAttachmentRule::SnapToTarget,
		true
	);

	if (OwnerCharacter.IsValid())
	{
		// 붙이기
		AttachToComponent(OwnerCharacter->GetMesh(), AttachRules, AttachSocketName);
		HitArea->IgnoreActorWhenMoving(OwnerCharacter.Get(), true);// 자기 자신이랑은 충돌 안하게 (만약을 대비)

		IWeaponUserInterface* WeaponUser = Cast<IWeaponUserInterface>(OwnerCharacter);
		if (WeaponUser)
		{
			// 콜리젼 토글 관련 델리게이트에 바인딩
			WeaponUser->GetWeaponAttackStateChangedDelegate().BindUFunction(this, FName("AttackEnable"));
			//WeaponUser->SetWeapon(this);
		}

		// 여기 밑은 사실 안봐도 됨
		if (TargetChanel == ECC_Enemy)
		{
			HitArea->SetCollisionResponseToChannel(ECC_Enemy, ECR_Overlap);
			HitArea->SetCollisionResponseToChannel(ECC_Player, ECR_Ignore);
		}
		else if (TargetChanel == ECC_Player)
		{
			HitArea->SetCollisionResponseToChannel(ECC_Player, ECR_Overlap);
			HitArea->SetCollisionResponseToChannel(ECC_Enemy, ECR_Ignore);
			HitArea->SetCollisionEnabled(ECollisionEnabled::QueryAndPhysics);
		}
	}
	
}
```

## 2 기타 팁
- On 붙은 이벤트 함수들은 외부에 공개하지 않는편이 좋음
- 데이터 에셋이나 구조체가 가지는 함수들은 로직을 가지면 안되고 데이터만 가공하거나 확인하는 용도로 존재해야함
- 에디터에서 뭔가 보여지고 싶으면 OnConstruction에서 진행해야한다. 유프로터나 같은거 바뀔때, 만들때
	- 사실 PostInitializeComponents도 좋음 액터의 모든 컴포넌트가 생성 되었을때
- StaticClass()는 해당 객체의 Uclass를 가져오는 것
