# rvalue, lvalue
직관적인 이해는 표현식 (expression)의 왼쪽, 오른쪽에 있는 값을 의미한다. 하지만 이런 방식의 설명은 모든 경우를 대변하지 못한다. 

```cpp file:lvalue,rvalue
int a = 3;
// 여기서 a는 lvalue, 3은 rvalue
```
## lvalue
주소를 취할 수 있는 값 또는 메모리에 존재하는 값으로 표현식의 좌변과 우변 둘 다 위치할 수 있다. 레퍼런스는 좌측값에 대해서만 가능한데 이는 앞선 개념으로 설명할 수 있다. `&`을 통해서 레퍼런스를 하려면 원본이 어디 있는지 알아야한다. 하지만 rvalue의 경우 바로 사라질 값이기 떄문에 원본을 알 수 없어 불가능하다. 하지만 `const T&`의 경우는 **우측값 참조를 받을 수 있다.**

## rvalue
주소를 취할 수 없는 값, 표현식을 지나면 사라질 값을 의미한다. rvalue는 표현식의 우변에만 위치할 수 있다. `&&`을 통해서 rvalue 레퍼런스를 사용할 수 있다. `MyObject&& obj`형태로 rvalue를 받을 수 있는데 여기서 obj 자체는 lvalue이다. 좌측값이지만 타입이 MyObject의 rvalue ref일 뿐이다. rvalue ref를 통해서 복사가 아니라 **이동**을 구현할 수 있다. 
rvalue ref의 특징 중 하나는 임시 변수(객체)가 소멸하지 않도록 붙잡는다.

## 이동
복사는 원본과 복사본이 따로 존재한다. 복사 실행시 원본의 내용을 복사해서 새로운 대상에서 넘겨준다.
하지만 이동의 경우 소유권을 넘겨 받는다. 곧 사라질 객체의 자원을 복사하지 않고 넘겨받는 방식. 기본 복사 생성자에서는 원본 객체의 주소를 복사본도 들고 있는 형태이다. 즉 2개의 객체가 같은 곳을 가리키는 방식이라 dangling pointer, double free 같은 문제가 발생할 수 있다. 
이동 생성자의 경우 포인터를 복사 하는 것 까지는 같은데 원본의 포인터를 nullptr로 밀어야한다. 이러면 임시 객체가 사라질 때 원래 값이 존재 했던 메모리를 삭제할 수 없다. 임시 객체가 가졌던 소유권이 다른 객체로 이동된 경우라고 볼 수 있다.
이동 대입 연산자의 경우도 동일하다.

## std::move
std::move는 lvalue를 rvalue로 캐스팅해주는 함수로 실제 객체를 이동 시키는 함수가 아님에 주의하자. 단지 이동이 가능한 상태로 만들어  줄뿐이다.
정확한 설명은 객체를 xvalue로 캐스팅한다. xvalue에 관한 설명은 [[Value Category]]를 참고하자. xvalue가 되었기 때문에 복사 대신에 이동이 가능해진다.
